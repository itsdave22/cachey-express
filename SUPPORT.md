# Support

## Bug reports

Use GitHub Issues for reproducible bugs in public behaviour, documentation or examples.

Before opening an issue:

1. Check that you are using the intended `@cachey/express` version.
2. Search existing issues for the same problem.
3. Remove secrets, tokens and personal data from logs and code samples.
4. Include a minimal reproduction when possible.

## Feature requests

Feature proposals are welcome through the feature-request issue template. Describe the problem first, then the desired behaviour and use case.

## Security reports

Do **not** open a public issue for a suspected vulnerability. Follow [SECURITY.md](./SECURITY.md).

## Commercial / product questions

Product information and future public documentation live at:

- https://cachey.eu
- https://cachey.eu/express

This public repository is not a place to expose private infrastructure, customer data or proprietary implementation details.
